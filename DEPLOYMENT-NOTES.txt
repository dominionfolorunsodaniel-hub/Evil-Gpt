VYRA SETTINGS, ZIP FILE GENERATION, AND CACHE REFRESH PATCH

Modified files:
- app.py
- templates/index.html
- static/script.js
- static/style.css
- static/sw.js

Included changes:
1. Chat composer is simplified to a compact settings chip instead of showing the full set of controls.
2. Fast/Balanced/Deep, assistant persona, reply language, and creativity now live in Settings > AI & Chat. Existing request payload controls are retained.
3. Settings has category navigation for AI & Chat, Personalization, Tools & Workspace, and Data & Security.
4. Creativity preference is persisted locally.
5. Added authenticated multi-file ZIP endpoint (`/api/export-files-zip`) with file count, size, duplicate name and path traversal checks.
6. Existing answer ZIP export now packages named code fences as separate files when a response uses a format such as ```index.html or ```file:src/app.js. If no named code files are found, it exports the answer as Markdown as before.
7. Added a project ZIP export interface in Projects & Memory. Select a project, paste a JSON array of `{path, content}` files, and export. Project ownership is checked server-side.
8. Service-worker cache version bumped and static assets switched to network-first caching with offline fallback. Asset URLs have a build version query to reduce stale frontend versions after deployment.

Deployment:
- Extract this ZIP and replace each included file in your existing repository at the same relative path.
- Commit to the existing deployment branch/service and redeploy.
- Close the old browser tab, then reopen VYRA. If testing for cache issues, compare normal browsing with Incognito.
- Test settings tabs, mode, persona, language, creativity, Tune reply, existing chat export, ZIP from named code blocks, and project ZIP export.
